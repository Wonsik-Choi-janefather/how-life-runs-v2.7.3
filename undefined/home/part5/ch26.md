# 26장 WRRA를 적용할 수 있는 생명공학

**WRRA를 적용할 수 있는 생명공학**

> WRRA의 실용성은 새로운 이름을 붙이는 데 있지 않고 복잡한 생명공학 과정의 누락된 실행층을 찾는 데 있다.

## 기존 학계의 출발점

iPSC, 오가노이드, 면역세포공학, 재생의학, 단백질설계와 바이오제조는 모두 유전정보와 환경제어를 결합한다. 실패는 종종 목표서열이 아니라 상태, 공정, 공간과 계보에서 발생한다.

## WRRA의 재구성

iPSC에서는 초기화 잔재와 분화순서, 오가노이드에서는 공간 niche와 경계, 세포치료에서는 체내 생존과 계보안정성, 단백질설계에서는 접힘과 복합체 조립을 핵심 renderer로 기록한다.

## 비교해 읽기

iPSC와 오가노이드에서는 같은 유전배경에서도 초기상태와 처리순서가 품질을 좌우한다. 세포치료에서는 투여 전 표현형보다 체내에서의 생존, 이동, 기능과 장기계보가 중요하다. 단백질설계에서는 계산된 구조가 실제 발현, 접힘, 복합체 조립과 세포환경에서 기능하는지 확인해야 한다.

WRRA가 생명공학 플랫폼으로 기여하려면 공정마다 SOURCE, STATE, RENDERER, BOUNDARY, OBSERVABLE, LINEAGE 필드를 표준화하고, 배치 간 실패를 이 필드로 예측해야 한다. 기존 품질관리보다 외부 배치 성능을 높이면 실용적 가치가 생기고, 그렇지 않으면 유용한 기록체계에 머문다.

> 해석과 예측의 경계 WRRA가 성공했다고 말하려면 기존 공정모형보다 외부 배치의 품질, 수율, 안전성 또는 실패예측을 개선해야 한다. 단순 재분류만으로는 예측적 기여가 아니다.

### 단백질·효소 설계의 WRRA 해석

서열의 이론적 기능은 SOURCE/Law 수준이고, 실제 발현·접힘·보조인자 결합·세포내 위치·독성·분해는 Renderer/State 수준이다. 따라서 서열 점수만으로 기능을 선언하지 않고, executor swap과 길이 holdout, 활성/수율의 분리, seed carryover 감사가 필요하다. 긴 단백질의 낮은 전장비율을 프로모터 하나의 문제로 흡수하지 않고 과정성·자원·구조·품질관리 층으로 분해할 수 있다.

## 실제 연구 사례: WRRA-Motor H2

WRRA-Motor H2는 ‘걷는 단백질’을 말로 상상하는 데서 멈추지 않고, 기존 kinesin-1의 검증된 실행부와 새로 설계한 조정부를 분리해 후보서열, 계산, 실패조건과 실험계획까지 남긴 실제 연구 진행 사례다. 후보 H2-b2f820d18e는 사람 KIF5B motor core 1–353 aa를 보존하고 32 aa coiled-coil WRRA gate를 더한 총 385 aa 단백질이다. 설계 gate 서열은 VQNIEQKIANLKEEGAAALQQVEQKIQNLKAE이며, 사람세포 발현을 가정해 역번역한 CDS는 stop codon을 포함해 1,158 nt다.

이 사례의 현재 판정은 PREDICTED\_SEQUENCE\_ONLY · 실제 보행 OPEN이다. 서열과 DNA 설계는 존재하지만 원자구조, 올바른 접힘, 이량체 보행, ATPase 보존과 cargo 수송은 아직 입증되지 않았다. 따라서 H2를 ‘보행단백질’이라고 부르는 것은 목표기능과 후보계보를 가리키며, 실험으로 닫힌 표현형을 뜻하지 않는다. 이 경계를 보존하는 것이 WRRA식 AI 공동연구의 첫 규칙이다.

### 최소 보행 계약에서 후보서열까지

설계 전에 ‘걷는다’의 최소계약을 동결했다. 두 개의 교대 접촉점, 평형을 깨는 에너지 입력, 극성을 가진 트랙, 현재 상태의 기록, 두 접촉점 사이의 조정이 모두 있어야 한다. 상태벡터를 Xₜ=(B\_A,B\_B,N\_A,N\_B,E,G)로 두면 B는 두 머리의 결합, N은 nucleotide, E는 에너지상태, G는 gate 상태다. 한 주기는 S₀(x)→S₁(x)→S₂(x+8 nm)→S₀(x+8 nm)로 기록한다. 단, 이 식이 8 nm 이동을 증명하는 것은 아니다. 물리계가 각 전이를 실제로 구현할 때에만 xₙ=x₀+8n nm가 성립한다.

방향성은 k₊/k₋=exp(A), A=(Δμ−W\_load)/(kBT)로 쓸 수 있다. 분리가 없다는 단순조건에서는 p₊=1/(1+exp(−A)), 평균 한 주기 변위는 d·tanh(A/2)다. Δμ≈20kBT, T=310 K, d=8 nm를 대입한 Fd<Δμ의 이상적 상한은 약 10.7 pN이지만, 이는 H2의 stall force 예측값이 아니다. 효율, 내부손실, gate 변형과 다중 경로를 제외한 에너지 경계일 뿐이다.

### 조건부 보행 시뮬레이션: 귀요미 H2의 첫 궤적

후보서열만으로 실제 속도와 분리율을 계산할 수 없으므로, 그림 6은 실측치를 가장하지 않고 ‘이 확률들이 맞다면 어떤 궤적이 나오는가’를 보여 주는 조건부 몬테카를로 실험으로 만들었다. 400개 motor가 최대 60 ATP 구동주기를 수행한다고 놓고, 각 주기에 전진 0.905, 후진 0.075, 트랙 분리 0.020을 가정했다. step은 8 nm, 난수 시드는 후보생성과 같은 260908로 고정했다. 분리된 motor는 그 위치에서 더 움직이지 않는 것으로 기록했다.

그림 6. WRRA-Motor H2의 기능 개념도와 실제 실행한 조건부 몬테카를로 시뮬레이션. 400회 평균은 60주기 뒤 240.5 nm였고 66.5%가 한 번 이상 분리되었다. 이 수치는 가정의 결과이지 H2의 측정값이 아니다. 단분자 TIRF나 optical trap 결과가 들어오면 확률을 추정값으로 교체하고 같은 코드로 예측–관측 차이를 계산한다.

재현 알고리즘은 간단하다. 매 주기마다 아직 부착된 motor에 대해 0과 1 사이의 난수 u를 하나 뽑는다. u<0.905이면 +8 nm, 0.905≤u<0.980이면 −8 nm, u≥0.980이면 분리로 기록한다. 400개 궤적의 평균, 10–90 백분위와 부착비율을 주기별로 계산한다. 독자는 seed·확률·주기수를 바꾸어 ‘방향성은 유지되지만 processivity가 무너지는 조건’이나 ‘하중 증가로 후진확률이 커지는 조건’을 먼저 탐색할 수 있다.

## WRRA Core 1.0을 내려받아 AI의 기준 문서로 만드는 법

공식 동결본은 https://doi.org/10.5281/zenodo.22650956에 공개된 WRRA Core 1.0: A Domain-Agnostic Execution Architecture다. 공개일은 2026-09-08, 버전은 1.0, 라이선스는 CC BY 4.0이다. Zenodo의 Files에서 영문 PDF 동결본을 내려받아 연구폴더에 원본 그대로 보존한다. 00\_manifest에는 Zenodo에 표시된 전체 파일명, DOI, 버전, 다운로드일과 MD5 b2c77039ab202a1f9da7baf1b1c9d3fc를 기록한다. 다른 사람이 같은 입력을 받지 못하면 AI 결과를 재현했다고 말할 수 없다 \[75].

여기서 ‘AI를 학습시킨다’는 말을 세 층으로 구분해야 한다. 첫째, 대화나 프로젝트에 PDF를 첨부해 기준문서로 참조시키는 것은 모델 가중치를 바꾸는 재학습이 아니다. 둘째, 문서를 조각내 검색색인에 넣고 질문마다 관련 절을 꺼내 주는 RAG도 외부 기억을 붙이는 방식이다. 셋째, fine-tuning은 다수의 입력–정답 예시로 모델의 응답행동을 조정하는 별도의 훈련이다. 처음부터 fine-tuning으로 Core를 암기시키기보다 원문검색과 인용을 유지하는 문서기반 방식이 개정·감사·오류수정에 유리하다.

| 프로젝트 / RAG  | 검색 가능한 외부 문서기억      | 장기 연구에 권장; 검색된 절과 답변을 함께 저장           |
| Fine-tuning | 응답패턴에 영향을 주는 모델 가중치 | 충분한 예시와 평가셋이 있을 때만; 최신 Core 검색은 계속 필요 |

문서기반 설정은 다음 순서가 안전하다. ① 새 연구공간을 만들고 Core PDF를 첨부한다. ② AI에게 해결책을 내기 전에 Core의 고정요소와 응용에서 선택 가능한 요소를 표로 복원하게 한다. ③ 답변마다 원문의 절·표현과 AI의 추론을 분리하게 한다. ④ 현재 문제의 Domain Profile을 작성한다. ⑤ 사람 연구자가 질문, 제외범위, 관측량과 중단조건을 승인한다. ⑥ 그 뒤에만 후보생성이나 계산을 허용한다. ⑦ 각 산출물에 입력문서, prompt, 모델·도구 버전, 날짜, seed와 실패후보를 함께 저장한다.

### 첫 대화에 그대로 넣는 기준 프롬프트

> 첨부한 WRRA Core 1.0 동결본을 이 연구의 헌법적 기준문서로 사용하라. Core 자체를 새 용어로 바꾸거나 누락하지 말라. 먼저 SOURCE→RELATION/LAW→STATE/RESIDUE→BOUNDARY→COMMON CARRIER→UPDATE→RENDERER→PHENOTYPE→OBSERVABLE/RECORD/LEDGER의 순서를 원문 근거와 함께 복원하라. 그다음 이번 문제를 Domain Profile로 변환하되, 사실 FACT, 입력 ASSUMPTION, 계산 DERIVATION, 후보 PREDICTION, 미해결 OPEN을 구분하라. 사람에게 확인받기 전에는 후보를 생성하지 말라. 검증기나 필요한 입력이 없으면 추측으로 채우지 말고 FAIL\_CLOSED와 null을 반환하라. 모든 결론에는 소유자, 입력자료, 계산 또는 인용근거, 반증조건을 붙여라. 먼저 (1) Core 재구성표, (2) 빠진 정보, (3) 사람이 결정할 질문만 출력하라.

AI가 Core 요약을 자신 있게 잘못 만들 수 있으므로, 첫 응답을 그대로 연구에 쓰지 않는다. 원문에서 최소 계산, common carrier, phenotype, fixed-present, ownership, boundary, renderer, record/ledger와 fail-closed가 모두 복원되었는지 사람이 대조한다. 누락이 있으면 관련 페이지를 다시 제공하고, 수정 전·후 답변을 장부에 함께 남긴다.

### AI 공동연구의 표준 실행순서

1\. 질문 동결 — ‘새 단백질을 만들어라’가 아니라 ‘극성 microtubule에서 ATP 의존적 8 nm 방향성 이동을 보이는 후보를 만들고 어떤 자료가 실제 보행을 판정하는지 정하라’처럼 관측가능한 목표를 쓴다.

2\. 근거 분리 — 표준 생물학, WRRA 재구성, 연구자의 가정, AI가 만든 후보와 아직 열린 항목을 서로 다른 열에 둔다. AI의 문장은 1차 근거가 아니므로 논문·데이터베이스 원문으로 되돌아간다.

3\. 최소계약 — 성공에 필요한 조건과 실패조건을 먼저 고정한다. H2에서는 두 접촉, 에너지, 트랙극성, 상태기록과 head coordination이 이에 해당한다.

4\. 기준선·음성대조 — P0, H1, generic coiled coil, scrambled gate와 같은 대조를 후보보다 먼저 정한다. 후보만 계산하면 좋은 결과가 나와도 무엇 때문인지 알 수 없다.

5\. 탐색과 provenance — AI가 구조군과 서열을 열거할 때 탐색공간, 필터, 점수식, seed, 탈락이유를 저장한다. H2에서는 64개 구조안과 512개 gate 후보를 거쳐 상위 5개를 남겼다.

6\. 독립 검증 — 같은 AI의 자기평가를 검증으로 쓰지 않는다. sequence QC, structure predictor, oligomer-state 분석, ATPase, 단분자 영상과 하중실험처럼 서로 다른 도구와 물리적 측정을 연결한다.

7\. 주장 장부 — ‘계산됨’, ‘예측됨’, ‘실험됨’, ‘독립재현됨’을 구분한다. H2는 현재 후보서열 계산과 DNA 역번역까지만 닫혔다.

8\. 사람의 최종 승인 — 연구자는 목표, 생물안전·윤리, 데이터 공개범위, 실험설계와 논문의 최종 문장을 책임진다. AI에게 과학적 소유권과 책임을 넘기지 않는다.

표 28D. H2에서 사람·AI·외부검증기가 맡은 일.

| **주체** | **주요 역할**                       | **맡기면 안 되는 판단**     |
| ------ | ------------------------------- | ------------------- |
| 사람 연구자 | 질문·범위·판정기준·안전·최종주장 승인           | 근거를 읽지 않은 자동승인      |
| AI     | 문헌구조화, 누락점검, 계산, 후보열거, 코드·초안 작성 | 실험하지 않은 기능을 사실로 선언  |
| 외부 도구  | 서열검사, 구조·oligomer 예측, 통계와 시뮬레이션 | 자기 점수를 생물학적 증명으로 대체 |
| 실험     | 발현·용해도·ATPase·단분자 이동·하중응답 측정    | 대조군 없는 단일 성공영상      |

### H2를 따라 하는 독자 실습

첫째 날에는 Core PDF와 위 기준 프롬프트만 사용해 H2의 Domain Profile과 OPEN 목록을 작성한다. 둘째 날에는 P0/H1/H2/C1/C2의 비교표를 만들고 각 측정이 어느 주장을 닫는지 연결한다. 셋째 날에는 그림 6의 확률을 바꾸어 forward bias와 detachment가 속도·run length에 미치는 영향을 계산한다. 넷째 날에는 AI에게 실험 결과를 가정한 세 개의 blind dataset을 만들게 하고, 미리 동결한 판정규칙으로 PASS/FAIL/OPEN을 분류한다. 마지막에는 AI가 처음 제안한 문장과 검증 뒤 허용되는 문장을 비교한다.

실험단계의 측정순서는 발현·용해도 → oligomer state → ATPase → microtubule landing rate → 속도와 run length → 두 머리 동시분리 빈도 → 하중응답이다. P0는 양성대조, B0는 motor core 단독, H1은 알려진 dimerization 교정, C1은 일반 coiled coil, C2는 scrambled gate로 둔다. H2가 발현되더라도 ATPase가 없으면 운동실행 실패이고, ATPase가 있어도 방향성 step이 없으면 보행 실패이며, 보행해도 cargo 운반이 없으면 수송주장은 OPEN으로 남긴다.

### 재현 가능한 연구 장부

연구폴더에는 00\_manifest, 01\_sources, 02\_prompts, 03\_domain\_profile, 04\_candidates, 05\_code, 06\_results, 07\_failures, 08\_claim\_ledger의 순서를 권한다. manifest에는 WRRA Core DOI·버전·checksum, 사용 모델과 도구의 정확한 이름·버전·날짜를 적는다. 각 후보에는 ID, 부모서열, 상속/설계 경계, 생성 prompt, seed, 필터와 탈락이유를 붙인다. 결과파일은 원자료와 가공자료를 분리하고, figure를 만든 코드와 매개변수를 함께 저장한다. 실패후보를 지우면 탐색편향과 사후선택을 감사할 수 없으므로 FAIL\_CLOSED 기록도 연구성과로 보존한다.

Fine-tuning은 이 문서기반 절차로 반복사례가 충분히 쌓인 뒤 고려한다. WRRA 준수 분석과 위반 분석을 예시쌍으로 만들고, 학습·검증·최종시험 세트를 분리한다. 평가지표는 멋진 문장보다 Core 필드 누락률, 근거 없는 closure 비율, provenance 누락률, 동일입력 재현성과 인간평가자 간 일치도로 잡는다. fine-tuned 모델도 Core 원문검색과 주장 장부를 계속 사용해야 하며, 동결본이 개정되면 새 버전으로 다시 평가한다.

공개되지 않은 환자자료, 특허전 서열 또는 기관 제한자료는 사용하는 AI 서비스의 보존·학습·공유정책과 연구윤리를 확인하기 전 업로드하지 않는다. 민감한 작업은 승인된 폐쇄환경이나 로컬 모델에서 수행하고, 공개본에는 필요한 최소 provenance만 남긴다. 재현성과 공개성은 개인정보·생물안전·지식재산권보다 앞설 수 없다.


### 서로 다른 연구를 공통 문법으로 연결하기

WRRA Core 1.0의 SOURCE, RELATION/LAW, STATE/RESIDUE, BOUNDARY, COMMON CARRIER, UPDATE, RENDERER, PHENOTYPE, OBSERVABLE/RECORD/LEDGER를 연구 비교의 기준으로 사용한다. 이는 Core를 변경하는 작업이 아니라 생명공학 자료에 적용할 Domain Profile이다. 각 기록에는 대상 시스템과 상태의 소유자, 출처, 관찰 조건, 시간·세대 및 주장 수준을 함께 붙인다.

논문과 발표자료는 하나의 통합 연구 지도에서 연결할 수 있다. 다만 서로 다른 세포주, 배지, 측정법과 시간창의 결과를 하나의 실험에서 얻은 자료처럼 합치지는 않는다. 비교 가능한 연결, 조건을 맞춘 뒤 비교할 연결, 현재는 직접 비교할 수 없는 연결을 표시한다. 같은 연구의 논문·발표·후속 요약은 근거의 계보를 연결하여 독립 재현으로 중복 계산하지 않는다.

처리 순서는 확인된 입력, WRRA에 따른 변환, 산출값, 실패 조건, 결론이다. 입력은 원문의 실제 관측과 계산 결과를 보존한다. 변환은 서로 다른 표현을 위 실행 요소에 대응시키고, 정보·자원·실행 장치가 다음 기능과 세대로 연결되는지 추적하는 것이다. 산출물은 근거 지도, 누락된 연결 목록과 비교 가능한 연구 질문이다. 실제 계산을 하지 않은 연결은 계산된 통합모형으로 표시하지 않는다.


### 다섯 항목을 함께 점검하는 기준

첫째, 실행 가능한 상속을 점검한다. 분열 사건, 각 딸의 필수 구성, 후속 기능 및 계보의 지속을 별도 결과로 남긴다. 어떤 딸의 관측이 빠졌거나 필요한 구성이 확인되지 않으면 해당 계보의 완결은 OPEN이다. 분열이 관측되지 않은 경우와 관측되었으나 후속 기능이 실패한 경우도 구별한다.

둘째, 자원 경계를 점검한다. 내부 재고, 외부 유입, 내부 생성·재사용, 외부 배출과 손실을 분리한다. 이미 만들어진 실행 장치의 공급을 내부 재생산으로 집계하면 자기유지에 관한 판정은 성립하지 않는다. 필요한 외부 흐름이 측정되지 않았다면 자율성의 범위를 확정하지 않는다.

셋째, 정보와 해석 장치의 연결을 점검한다. 유전정보, 이를 읽는 장치의 현재 상태, 활성 산물과 기능 출력 사이의 연결을 각각 확인한다. 정보가 존재한다는 사실만으로 기능을 추정해 채우면 실행 주장에 필요한 근거가 누락된다. 중간 단계가 미측정이면 그 연결을 가설로 표시한다.

넷째, 개별 계보와 총량을 동시에 점검한다. 부모·자식 관계의 단절, 식별자 중복, 측정 시점의 불일치를 먼저 확인한 뒤 전체 수지와 대조한다. 합계의 일치만으로 특정 계보의 실행 가능성을 보증하지 않는다. 추적 해상도가 분자군 수준이면 개별 분자의 이력은 식별 불가로 남긴다.

다섯째, 관측과 제어를 구분한다. 무엇을 측정했는지, 무엇을 상태로 추정했는지, 어떤 개입의 효과를 평가했는지와 그 비용을 분리한다. 관측 적합만으로 개입의 성공을 선언하면 제어 주장은 성립하지 않는다. 상태 추정이나 모형의 불일치가 확인되면 그 원인을 제어 효과와 분리해 기록한다.


### 감사 장부의 필수 기록

한 행은 하나의 주장 또는 하나의 상태전이를 나타낸다. 기록 ID와 원문 위치, 대상·소유자와 시간·세대, 출처 및 근거 유형, 실행 요소와 선행 의존성, 단위·불확실성, 외부 지원, 산출값, 실패 조건과 현재 판정을 기록한다. 실험 관측, 저자 모형의 산출, 본 책의 재계산과 새 가설은 서로 다른 근거 유형이다. 전사량·단백질량·활성·생존을 하나의 성공 수치로 대체하지 않는다.

현재 재고의 변화는 시작 재고에 유입과 생성을 더하고, 유출과 소비를 빼는 수지로 점검할 수 있다. 이때 같은 분자종·구획·시간창·단위를 사용하고, 내부 이동을 전체 시스템의 새로운 유입으로 중복 계산하지 않는다. 분자종은 반응으로 생성·소비될 수 있으므로 단순 분자 개수의 보존과 원소 수준 물질수지를 혼동하지 않는다. ATP 회전량, 질량과 기능 활성은 서로 다른 장부에 둔다.

차이가 남으면 즉시 생물학적 손실로 결론 내리지 않는다. 검출한계, 누락된 흐름, 시점 차이, 오차모형과 변환 규칙을 먼저 검토한다. 미측정 항목은 null과 사유로 남기며, 허용 오차와 중단 기준은 결과에 맞추어 바꾸지 않는다. 이 기록은 누락과 중복을 감사할 수 있게 하는 제안된 규격이다. 실제 자료가 입력되고 검사가 실행되기 전에는 구현 완료로 표시하지 않는다.


### 공통 문법의 효용을 검증하는 방법

첫 적용에서는 범위가 작은 기능 집합과 동일한 자료 묶음을 정한다. 기존의 문헌 정리 방식과 WRRA 장부 방식이 찾은 근거 연결, 잘못 연결한 항목, 누락, 검토 시간 및 연구자 간 판정 일치도를 대조한다. 전문가가 근거 위치를 다시 확인하여 표현만 정돈된 것인지, 실제 검토 부담과 오류가 줄었는지 평가한다.

조건과 출처를 보존해 비교 가능한 연구 질문을 더 명확히 만드는 것은 독립적인 실용 성과다. 알려진 값을 재구성한 설명의 성과도 그 범위에서 인정한다. 새로운 미래 예측이나 제어 성과는 별도의 검증 대상으로 둔다. 공통 문법의 추가 이익이 관찰되지 않으면 적용 범위와 장부의 복잡도를 줄인다. AI의 자동 분류·연결 능력과 인간의 검토 부담 감소는 검증할 대상이며, 이미 입증된 성능으로 가정하지 않는다.
